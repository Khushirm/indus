Research Proposal: LLM Agents for Indus Script Hypothesis Testing

M.Tech Computer Engineering · Semester research project · Draft of 17 October 2026
Working title Propose, Test, Reject: An LLM-Agent Framework for Falsifiable Hypothesis Testing on the Undeciphered Indus Script

This project does not try to decipher the Indus script. It builds and evaluates a system in which LLM agents propose structural hypotheses about the script, and a statistical verifier accepts or rejects each one against the corpus. Example hypotheses: "sign X is a numeral", "sign Y marks the end of a word", "these two signs are variants of one sign".

The framework is first checked on scripts that are already deciphered, with their known answers hidden. Only then is it applied to the Indus corpus. Expected contributions: (1) a reusable framework, (2) a benchmark of hidden-answer tests on known scripts, and (3) a ranked, reproducible list of Indus sign hypotheses that survive testing.

1. Problem and motivation

The Indus script is one of the best-known undeciphered writing systems, and computational methods have so far settled little about it. More than 100 decipherment attempts have failed (Scroll, 2025).

  • No bilingual text. There is nothing like the Rosetta Stone, and the underlying language is unknown.
  • Very short texts. The ICIT corpus has about 5,509 texts and 19,616 sign occurrences, so a typical text is only a few signs long. Standard neural decipherment needs far more context than that.
  • Disputed status. Researchers still disagree on whether the signs encode language at all. Rao et al. (2009) argued yes using entropy. Sproat (2014) applied related measures to more corpora and classified the Indus inscriptions as non-linguistic.
  • Why now. On 5 January 2025, Tamil Nadu announced a USD 1 million prize for a decipherment and Rs 2 crore for a research chair named after Iravatham Mahadevan (Deccan Herald). LLM agents now make it cheap to produce hypotheses in bulk, which creates a new risk: claims that sound plausible but are wrong.

This project treats that risk as the research problem. LLMs can propose hypotheses, so the useful question becomes which hypotheses survive rigorous, pre-specified testing.

2. Related work

Statistical analyses of the Indus script

  • Rao et al. (2009, Science) compared the script's conditional entropy with linguistic and non-linguistic systems and found it closer to language.
  • Sproat (2014, Language) found that the earlier measures don't separate writing from non-writing when tested on a larger set of corpora. Using his own measures, he classified the Indus and Pictish symbols as non-linguistic. Yadav, Jonathan and Ziman published a rebuttal in Language.
  • Raghavendra (2026, arXiv 2608.02999) builds a synthetic non-linguistic emblem system called SIGIL. The preprint reports that SIGIL passes the same statistical tests that are used as evidence for language in the Indus script. read first This matters directly to this project: the verifier cannot rely on those tests alone.

Neural decipherment of known scripts

  • Luo, Cao and Barzilay (ACL 2019) mapped Ugaritic and Linear B onto known related languages using sequence-to-sequence models trained as a minimum-cost flow problem. They report correctly translating 67.3% of Linear B cognates.
  • Luo, Hartmann, Santus, Barzilay and Cao (TACL 2021) jointly modelled word segmentation and cognate alignment, using phonetic (IPA) priors. They tested on Gothic and Ugaritic and applied the method to undeciphered Iberian. Their code is public.
  • Limitation for Indus: both methods assume a known related language. That assumption is exactly what is missing for the Indus script.

Machine learning on Indus images

  • Palaniappan and Adhikari (2017, arXiv 1702.00523) built a deep-learning pipeline that turns photos of inscriptions into standardised sign sequences.
  • "Deep Learning in Archiving Indus Script and Motif Information" (Journal of Computer Applications in Archaeology) continues that line of work.

3. Gap, research questions, contributions

Gap: Earlier work either tests one fixed hypothesis by hand (the entropy papers) or assumes a known related language (the neural decipherment papers). No existing system generates many candidate structural hypotheses and tests each one against controls with known answers.

  1. RQ1: On deciphered scripts with their answers hidden, what share of the hypotheses that LLM agents propose does the verifier correctly accept? This is precision, or the false-discovery rate.
  2. RQ2: How much does each component (verifier, critic, held-out split) reduce false discoveries compared with an LLM working alone?
  3. RQ3: Which Indus hypotheses survive the same pipeline, and how do they compare with what scholars already claim, for example that certain stroke signs are numerals?

Contributions: an open-source framework, a benchmark of hidden-answer tests, and a ranked list of Indus hypotheses with code to reproduce it.

4. Proposed method

1. ProposerLLM reads corpus statistics and suggests hypotheses in plain language
→
2. FormalizerTurns each hypothesis into an executable test (a Python predicate plus a test statistic)
→
3. VerifierRuns the test on held-out data against null models, with multiple-comparison correction
→
4. CriticLLM looks for confounds such as site, object type or sign frequency
→
5. LedgerLogs every hypothesis, test and verdict; rejections go back to the Proposer

The verifier is the core contribution. It uses no LLM, so an accept or reject decision never depends on what an LLM merely finds convincing.

Hypothesis types (scoped to what short texts can support)

  • Positional: sign X occurs at the start or end of texts more often than chance.
  • Numerals: stroke-like signs combine in ways that follow a counting system.
  • Allographs: signs A and B appear in the same contexts, so they may be variants of one sign.
  • Segmentation: a recurring sign pair or triple behaves like one unit, such as a word.
  • Context dependence: a sign's frequency depends on the site, object type or period.

Verifier design (this is what reviewers will look at hardest)

  • Split the corpus before starting. The Proposer only sees the exploration split. Every test runs on a held-out confirmation split.
  • Null models: shuffled corpora that keep sign frequencies, plus synthetic non-linguistic systems in the style of SIGIL.
  • Permutation tests, with Benjamini–Hochberg correction across all hypotheses tested.
  • Pre-registration: each test is fixed in the ledger before it runs, which blocks p-hacking.
  • Open-weight LLMs (for example Llama or Qwen), so other researchers can reproduce the results.

6. Evaluation plan

Hidden-answer tests on deciphered scripts

  1. Take a deciphered corpus, replace every sign with an anonymous ID, and cut the texts to Indus-like lengths.
  2. Run the full pipeline on it.
  3. Score the accepted hypotheses against the known answers, for example which signs are numerals and where word dividers fall.

Contamination check: LLMs have read a lot about Linear B. Anonymising the signs and hiding the script's name is what keeps the test fair. Also check directly whether the model can recognise which script it is looking at.

MetricWhat it shows
Precision / false-discovery rateHow often an accepted hypothesis is actually true
Recall of known factsHow many of the planted ground-truth facts the system recovers
Accept rate on null corporaShould be close to zero; checks that the verifier isn't fooled
Cost per accepted hypothesisTokens and runtime, which shows the approach is practical

Ablations: LLM alone with no verifier; no critic; no held-out split; different LLM sizes.

Indus results: report the surviving hypotheses with effect sizes and compare them with claims already in the literature. Present them as candidates for experts to examine, never as decipherments.

8. Risks and mitigations

RiskMitigation
Can't get ICIT accessDigitise a subset of the Mahadevan concordance. The control-script benchmark still makes a publishable paper on its own.
Statistical tests can't tell language from non-language (Sproat 2014; Raghavendra 2026)Make this part of the design: every test also runs on non-linguistic null systems, and only hypotheses that separate from them count.
Texts too short for tests to detect real effectsRestrict to hypothesis types that suit short texts (positional, co-occurrence) and report statistical power
LLM has memorised the control scriptsAnonymise signs, hide script names, and run the contamination check
OverclaimingSay in the abstract that this is not a decipherment; describe outputs as candidates for experts
API costsRun open-weight models locally or on a college GPU; cache LLM calls
